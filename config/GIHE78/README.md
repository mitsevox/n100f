# GIHE78 target configuration

USA release, disc revision 0. `main.dol` is 1,964,512 bytes with entry point `0x80016898` and SHA-1 `c77fb29d39b5898933e8ef4d1ccd2ddac404554e`. `.bss` starts at `0x801DF1C0` with size `0x83B34`. The disc has no linker map or symbols.

## Mapping onto the handbook stages

| Handbook stage | Implementation |
| --- | --- |
| Original-byte baseline | dtk splits the DOL into original objects, which every object not marked `Matching` links unchanged; `ninja` relinks the DOL and checks `build.sha1` |
| Accepted-source build | Objects marked `Matching` in `configure.py` replace their split ranges; the complete DOL must still match `build.sha1` |
| Independent comparisons | Objects marked `NonMatching` stay in their normal `src/` files; objdiff measures them against the split target objects while the original bytes remain linked |
| Promotion | Change the object from `NonMatching` to `Matching` after review; the source path does not move |

`Equivalent` objects and `--non-matching` builds are local diagnostics and never count as linked progress. Per-object `cflags` overrides need the same unit-level evidence as library profiles.

## Baseline

The initial `symbols.txt` and `splits.txt` were generated by patched dtk 1.8.3 analysis (see the README). The relink is byte-identical to the target. Two target facts need care:

- The DOL entry point `0x80016898` is a routine in `.text` that paints the stack and then calls `__start` at `0x80005304`. Stock dtk therefore misses `_rom_copy_info`, which is why the patch exists. `tools/project.py` passes the entry to mwld with `-m`, because the linker otherwise requires `__start` as the entry.
- mwld places `_rom_copy_info` and `_bss_init_info` in the section that holds the global `__start`, so `0x80005304` must keep that name for the relink to match. Every mwld version tested gives the same output, so the linker version is not yet established. See the `linker` row in [evidence.tsv](evidence.tsv).

## Status

Compiler profiles are in the `compiler` rows of [evidence.tsv](evidence.tsv) and in [docs/compiler_profile](../../docs/compiler_profile/README.md): GC/1.3.2 for game code (`cflags_game`) and GC/1.2.5n for the SDK. MetroTRK is GC/1.3, MSL is GC/1.3 with `-inline auto,deferred` and `-char signed` (`cflags_msl`), and the runtime is GC/1.3.2 (`cflags_runtime`). `mw_comment_version` is 10, which is what GC/1.3 and GC/1.3.2 write; the SDK units carry `comment:8` in `splits.txt`, as GC/1.2.5n writes. Library build configuration and headers are described in [docs/libraries.md](../../docs/libraries.md). The report-v1 export is described in [docs/public_report.md](../../docs/public_report.md). The validate workflow builds this baseline in the n100f-build image on every PR and `main` push.
